# Learn — Interest → Need → Thread → Real-World Proof

Method 4 of MindVault. Designed from the grilling session of Aug 11, 2026, from the User's own answers: interest-driven learning that dies of scattered interests; learning sticks when it's *needed*; the User returns for visible progress; progress = real-world proof; the AI tracks automatically; daily one-minute feed; needs decide what stays active.

## The five rules

1. **Needs decide.** A thread is active only while attached to a real need — a concrete thing it's FOR. No live need → automatic move to the shelf. No shame.
2. **Capture everything, active only some.** Every interest gets captured to the curiosity shelf (`shelf.md`); only threads with live needs are active in `threads.md`.
3. **Progress = real-world proof.** The only thing that advances a thread is evidence the learning changed something done in the real world. Notes about learning don't count; "used it" does.
4. **Daily minute (~1 minute).** The User logs one line — what they learned/did/touched. The AI files it: connects it to the right thread, updates status and proof, checks need liveness, shelves dead-need threads. Missing days are fine — never shame, never chase.
5. **The AI tracks automatically.** Mnemosyne (the AI's memory) remembers threads + needs across sessions, auto-captures interests noticed in conversation, and surfaces dormant threads when they resurface. The vault stays the durable record — state is never only in the AI's memory.

## Files

- `threads.md` — active threads: thread → need → status → last real-world proof. Closed threads archived at the bottom.
- `shelf.md` — curiosity shelf: captured interests without a live need.
- `daily.md` — the daily minute log (dated, append-only).

## Cold start

Missing days are fine. Reopening = read `threads.md`, say what moved (or "nothing"). No shame, no guilt.

## Closing a thread

A thread closes when its need is met or dropped: record the final proof, move it to Closed in `threads.md`.
